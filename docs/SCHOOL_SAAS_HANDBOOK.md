# School SaaS --- System Handbook

**Version:** V1 --- 2026-09-26\
**Purpose:** المرجع الأعلى لفهم النظام وتشغيله وتهيئته ومتابعة حالته.

## 1. فكرة النظام

School SaaS نظام مدارس متعدد المدارس والسنوات والأدوار. الويب وتطبيق
Flutter عملاء لنفس Backend وقاعدة البيانات، ولا توجد بنية Backend منفصلة
لكل عميل.

## 2. المبدأ المركزي: Active Context

السلطة في الطلبات الجديدة هي: - `request.active_membership` -
`request.active_school` - `request.active_role` -
`request.active_academic_year`

الحقول القديمة على `request.user` توافقية فقط وليست مصدر صلاحية في
التطوير الجديد.

## 3. تعدد الأدوار والسياقات

الحساب الواحد قد يملك أكثر من عضوية/دور، مثل: - معلم في مدرسة. - معلم في
مدرسة أخرى. - ولي أمر في مدرسة. - طالب في سياق آخر عند الحاجة.

اختيار العضوية النشطة هو الذي يحدد المدرسة والدور والسنة والسلوك. لا
يلزم إنشاء حساب منفصل للمعلم إذا كان ولي أمر أيضًا.

## 4. خريطة الاعتماد الوظيفي

``` text
School
  ↓
AcademicYear
  ↓
AcademicTerm
  ↓
Classroom
  ↓

  ↓

Student

  ↓

```

## 5. قاعدة السنوات التاريخية

السياق التاريخي للقراءة فقط. يجب ألا تظهر فيه عمليات حالية زائفة أو
إجراءات كتابة مثل تسجيل حضور حالي أو نشر واجب أو إدخال درجات قابلة
للحفظ.

## 6. أهم الفروق الوظيفية

### ClassSubject

بنية المنهج: المادة المرتبطة بالصف وما يرتبط بها من إعداد أكاديمي مثل
الحصص الأسبوعية.

### TeacherAssignment

التكليف التشغيلي: من هو المعلم الذي يدرّس مادة محددة لصف/شعبة في سنة
دراسية محددة. وهو أساس مهم لصلاحيات المعلم في الجدول والطلاب والحضور
والواجبات والاختبارات والتواصل.

## 7. التطبيقات

### Student Mobile V1

مغلق وظيفيًا، ويشمل الأساس المعتمد للطالب مثل السياق، الجدول،
الحضور/النتائج/الواجبات بحسب العقود الموجودة، الاتصالات، والمزيد.

### Teacher Mobile

-   M2-BE Shared Backend: مكتمل.
-   M2.1 Shell & Context: مغلق.
-   M2.2 Timetable: مغلق — مقبول وقت التشغيل.
-   M2.3 Assignments + Lesson Roster: مغلق — مقبول وقت التشغيل.
-   M2.4 Attendance: مغلق — مقبول وقت التشغيل.
-   M2.5 Homework: مغلق — مقبول وقت التشغيل.
-   M2.6 Exams & Results: مغلق — مقبول وقت التشغيل.
-   M2.7 Communications: مغلق — مقبول وقت التشغيل.

هذا هو الترقيم الحالي المعتمد. يفتح `TeacherShell` شاشة
`TeacherWorkCenterScreen` التي تضم `TeacherHomeworkScreen` وتجربة
Exams/Results.

تدعم الاتصالات الإشعارات ودورة حياة الإعلانات ومحادثات Teacher → Student.
إنشاء Teacher → Parent مؤجل حتى يتوفر عقد آمن لاكتشاف أولياء
الأمور/الأوصياء ضمن نطاق المعلم؛ معرفات العضوية الخام ليست بديلًا مقبولًا.

### School Admin Web

البنية الأكاديمية للصفوف والشعب والمواد مكتملة. مسار W10 للاختبارات والنتائج
مدمج، وإصلاح النشر التزايدي للنتائج مدمج. لا يعني ذلك اكتمال School Admin
Web Portal V1 بالكامل؛ تظل البوابة قيد العمل ولا تُستنتج حالة مراحل W الأخرى
من جاهزية Backend وحدها.

### Release 1.0 UI/UX

تبقى مراجعة/إعادة تصميم UI/UX للموبايل والويب مسار عمل رسميًا ومخططًا بعد
استقرار المعالم الوظيفية، مع الحفاظ على قواعد العمل وعقود API المعتمدة.

## 8. قاعدة التوثيق

كل طبقة توثق ما تملكه في مجلدها. الوثائق المركزية لا تُعدل تلقائيًا من
Agent واحد عند كل تغيير؛ تُحدّث عند اعتماد ودمج المراحل.
